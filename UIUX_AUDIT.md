# ErrandGuy — UI/UX Pro Max Audit

Senior-PD audit of every screen against the **UI UX Pro Max Skill** (installed at `.claude/skills/ui-ux-pro-max/` — 99 UX guidelines, priority ladder: Accessibility → Touch → Performance → Style → Layout → Type/Color → Animation → Forms → Navigation). Method: one auditor per screen + one flow-level consistency auditor, every finding pinned to `file:line` and a named skill rule, then implemented flow-by-flow. **Evolve, don't redesign** — all existing workflow and business logic preserved.

**Design-system decision (applies to every flow).** The skill engine's generated palette (appetizing-orange delivery) was **rejected** in favor of the skill's own higher-priority rules (`consistency`, `color-semantic`, token-driven theming): ErrandGuy already has a coherent semantic token system — brand-blue ramp, surface/ink/divider tokens, a 4-tier `Elevation` scale, a responsive `mScale` system — refined in the Phase-1 design pass. The audit therefore *hardens* that system instead of replacing it. Token additions this pass: `successDark #15803D` / `warningDark #B45309` (+ dark-mode rungs) — the "status text below 17px" rungs mirroring `dangerDark`; `Input` placeholder promoted `dividerStrong → textMuted`; `Input` error text promoted `danger → dangerDark`.

## Flow 1 — Authentication

Screens: welcome · role-select · login · register · verify-otp · forgot-password · permissions · contacts-permission (+ shared: Input, OTPInput, Button, SocialLoginButton, LegalModal, OnboardingSlide, useCountdown, useBiometricUnlock).

### Flow-wide verdict

**Strengths (keep):** primary-CTA discipline (every screen: one shared `Button size="lg"` 54pt with loading/disabled wired); the haptics idiom applied uniformly with zero double-buzz; genuinely strong a11y coverage (roles+labels on all icon buttons, live regions, `accessibilityState` on toggles, decorative art hidden); best-in-class OTP mechanics (SMS autofill, paste distribution, hitSlop back-fill, reduce-motion-aware shake); humane, status-mapped error copy with 422→inline field mapping.

**Root weakness:** the screen *chrome* (back button, title, eyebrow, subtitle, footer link) was built per-screen, not from shared specs — five small elements each shipped in 2–4 variants, which is where nearly all perceived inconsistency came from. Second: the canvas is unresolved (register = hero + white card; login/verify/forgot = flat `bg-background`) which made the muted-fill `Input` nearly invisible at rest on the flat screens (~1.01:1 fill-vs-canvas).

### Normalized auth chrome kit (now the single spec, applied everywhere)

| Element | Spec |
|---|---|
| Canvas | `bg-surface` (white) for form screens; register's tinted hero stays the flow's only band |
| Back button | 40×40 `rounded-full bg-surface border border-divider`, ChevronLeft 22 `ink` sw2.2, 24pt inset, hitSlop 10 |
| Eyebrow | `text-[11px] font-montserrat-bold uppercase text-primary`, tracking 1.8 |
| Title | `text-[28px] font-montserrat-bold text-ink`, letterSpacing −0.4, lineHeight 32, no trailing period, `accessibilityRole="header"` (permission screens: 26px bold) |
| Subtitle | `text-[15px] font-montserrat text-textSecondary mt-2` |
| Footer switch-link | `Pressable` (pressed opacity 0.55, hitSlop 12): prompt 14px `textTertiary` + link 14px `font-montserrat-semi text-primary`; copy **"Log in"** everywhere |
| Forms | react-hook-form `mode:'onTouched'` + blur passthrough; return-key chaining via new `Input` ref API; 422s inline via `setError` |
| Width | `contentMaxWidth` clamp (repo's own responsive contract) on every top-level scroll container |
| StatusBar | hoisted once into `(auth)/_layout.tsx` (`expo-status-bar`, `style="dark"`) |

### Shared-component upgrades (affect all flows)

- ✅ **Input.tsx** — `forwardRef` + `InputHandle {focus, blur}` (enables keyboard "next" chaining); placeholder `textMuted` (was `dividerStrong`, ~1.6:1 — a WCAG failure on every form in the app); error text `dangerDark` (12px `danger` was ~3.8:1); optional `rightIconColor`.
- ✅ **useCountdown** — rewritten deadline-based + AppState resync: JS timers freeze in background, and backgrounding (to read the SMS) is *the* primary behavior on the OTP screen; the timer now snaps to true remaining time on return. API unchanged.
- ✅ **OTPInput** — visible focused-cell state (2px primary ring, per `focus-states`); refocus-to-first-cell after a failed attempt (focus/render desync fix); error text `dangerDark`; iOS `announceForAccessibility` (the `accessibilityLiveRegion` prop is Android-only); reserved error line (no CTA jump); optional `success` prop (green cells beat before route swap).
- ✅ **Tokens** — `successDark`/`warningDark` in `colors.ts` + `tailwind.config.js`.
- ✅ **PermissionPrimer** (new `src/components/auth/PermissionPrimer.tsx`) — the two permission screens were ~95% duplicated *and silently diverged* on post-grant behavior; extracted into one component (user rule: reusable components over duplicated UI).

## Flow 3 — Booking funnel (type → details → schedule → review → confirm)

**Verdict:** the funnel's bones are genuinely strong — persisted 24h draft envelope, honest 30-day/30-minute scheduling bounds, estimate-failure recovery, deadline-based search countdown with real progressbar semantics — but the audit found the *connective tissue* broken in ways that cost conversions: the schedule quick-picks never actually seeded the wheel picker (users could submit a time contradicting every visible control), a rehydrated draft could **book as Cash while the UI showed GCash**, backing out of details destroyed both confirmed addresses, the advertised discard guard was unreachable dead code, and the time wheels were a screen-reader dead end. 72 findings (20 🔴) from 6 auditors; 69 implemented + 8 verified-skips; then the first **Polish & Layout Validation Pass** re-inspected the result and caught 89 more layout/device issues (all fixed).

### Shared foundation (built first, consumed by the bundles)

### Tracking — the redesign (a design bake-off, not a single attempt)

## Flow 8 — Runner Settings (×8) · Shared/System (root redirect · payment-return · root chrome)

**Verdict:** the last surface — the runner's stationary config screens plus the **app-wide system chrome that shapes every launch**. ### 8.1 Shared/System — the highest-leverage fixes (`index.tsx` · `payment-complete.tsx` · `_layout.tsx` · `app.json`)
🔴✅ **Runners flashed the customer navigator on every cold start** — `index.tsx` redirected on a not-yet-hydrated `role` (null until the profile fetch resolves), so a runner dropped into the *customer* tabs for a beat — wrong tabs + stray customer fetches — before `_layout` bounced them back. The naive `role==null → hold` was **verified unsafe** and rejected: a post-OTP role-less account would hang forever, and an offline cold-start would never resolve. Final fix branches on what's actually known — `user && role==null` → continue registration at `role-select`; a **3s grace-timer** falls through to the default navigator on a failed/offline fetch; otherwise a **branded splash** (reusing `logo-new.png`, the *same asset the native splash uses*, for a seamless handoff) holds until `role` resolves. 🟡✅ **payment-complete claimed success for every return** — it rendered `SuccessCheck` + "Payment received" unconditionally, but the return deep link carries **no status** (verified against `browser.ts`) and the Xendit **webhook is the real source of truth**. Made honest-neutral: a `Spinner` + "Finishing up… your balance updates once payment is confirmed" — the app never asserts a payment it can't confirm — plus a manual **Continue** CTA so a stalled auto-redirect is never a dead end. 🟡✅ the two redirect authorities (`index` vs `_layout`) were reconciled so a returning onboarded user lands on **login, not the first-run welcome carousel**; `app.json` `userInterfaceStyle` `automatic → light` (was leaking system dark mode into a light-only app); `StatusBar` owners added and the offline banner kept clear of the status-bar icons; the branded-splash background aligned to `#F7F8FA`.
